# Enterprise 2.0 staging
Apply in order on a separate test database: enterprise-tickets.sql, enterprise-members.sql, enterprise-ticket-extras.sql, enterprise-ticket-career.sql, enterprise-hardening.sql. Deploy updated tp-background-push only after the database is ready. Existing admins are enrolled automatically, other users require administrator activation. Shared company directory is separate from existing personal companies. All active members can read ticket content and existing solution rows, so review the legacy solution contents before rollout. Linked ticket tasks are created on import (or on close for exactly-once task XP); closing must occur from Ticket Center. Four ticket awards are additional to the original 50. No production deployment. CI uses synthetic fixtures, not production data; it does not replace real Supabase Auth/Storage/push and concurrent-user acceptance tests. Before production: verify legacy security-definer RPC and storage membership gates in real Supabase, test invitation and recovery flows, verify cron, prepare backups and approve company privacy/retention.

The isolated CI fixture includes callable legacy RPC stubs, storage policies, and checks deactivated users, exactly-once reminder scheduling and push lease claims. Actual email and browser push delivery still require a dedicated staging deployment.

## Preview artifact
The enterprise workflow now executes the complete legacy smoke suite and races two separate PostgreSQL clients for one ticket. On success it creates a downloadable staging preview artifact, never a GitHub Pages deployment. Set repository variables TP_STAGING_URL and TP_STAGING_PUBLISHABLE_KEY to an independently provisioned Supabase project; otherwise login is deliberately disabled. The builder rejects the production project URL. The organization is on the free plan; no new billable Supabase project or branch is created automatically. Preview artifacts must be served on a separate origin (or localhost) from production to isolate browser storage and service workers. For real auth and push tests configure the staging redirect and function origins before starting the test.
